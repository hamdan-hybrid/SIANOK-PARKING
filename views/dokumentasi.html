Dokumentasi API

API untuk perangkat Interface di gate (kendaraan masuk, update IP, buka gate), API laporan omset untuk bot WhatsApp, dan standar SDK QRIS serta SDK uang elektronik.

1. Ketentuan umum

  • Semua permintaan GET, tanpa login.
  • Alamat server harus memakai IP server (bukan domain), misalnya http://192.168.18.240:3003.
  • Pengirim harus berada di jaringan lokal yang sama dengan server. Selain itu dijawab 403 {"status":false,"pesan":"Access denied"}.
  • KEY = API key Interface (32 karakter), disalin dari menu Perangkat (tombol kunci).
  • Bila IP Interface sudah diisi di menu Perangkat, IP pengirim harus sama dengan IP tersebut.
  • Semua respons JSON: status (true/false) dan pesan.

2. Kendaraan masuk

GET/api/gate/masuk
http://IP-SERVER:3003/api/gate/masuk?id_gate=KEY&jenis_kendaraan=motor&rfid_member=&metode_masuk=tiket
ParameterKeterangan
id_gateWajib. API key Interface.
jenis_kendaraanWajib. Misalnya motor / mobil. Untuk member boleh kosong bila langganan hanya punya satu kendaraan (jenis diambil dari data langganan).
rfid_memberOpsional. Nomor kartu RFID langganan. Bila diisi, metode otomatis member.
metode_masuktiket (bawaan), member, qr, anpr, manual.

Proses di server

  1. Cek API key dan IP pengirim.
  2. Member: cek kartu RFID terdaftar, langganan aktif, dan belum tercatat di area.
  3. Simpan transaksi dengan no. tiket 10 digit (status in).
  4. Metode tiket: cetak tiket ke printer yang terhubung ke Interface.
  5. Kirim perintah buka gate ke Interface (lihat bagian 4).
  6. Ambil foto dari kamera yang terhubung ke Interface di latar belakang (±2 detik).

Respons berhasil (200)

{
  "status": true,
  "pesan": "Silakan masuk",
  "no_tiket": "6943224415",
  "gate": "GATE MASUK",
  "jenis_kendaraan": "motor",
  "metode_masuk": "tiket",
  "member": null,
  "nopol": null,
  "foto_diproses": 1,
  "cetak": true,
  "cetak_diulang": false,
  "peringatan": [],
  "gate_dibuka": true
}
  • Member: pesan = "Selamat datang, NAMA", member berisi nama pelanggan, nopol diisi dari kendaraan langganan yang cocok.
  • cetak: null bila tidak mencetak (bukan metode tiket). Printer yang belum merespons dicoba ulang di latar belakang sampai 10 kali; alasannya tercatat di peringatan.
  • gate_dibuka: true bila perintah buka gate sudah dikirim (IP Interface terisi).

Respons gagal

KodePesan

400metode_masuk harus salah satu: tiket, member, qr, anpr, manual
400rfid_member wajib untuk metode member
403Access denied (bukan jaringan lokal / lewat domain)
403IP x.x.x.x bukan IP perangkat NAMA

3. Update IP

GET/api/gate/update-ip

Dipanggil Interface saat menyala atau IP-nya berubah (DHCP), agar server tahu alamat untuk perintah buka gate.

http://IP-SERVER:3003/api/gate/update-ip?apikey=KEY&ipaddrs=192.168.18.30:80&sn=SERIAL123
ParameterKeterangan
apikeyWajib. API key Interface (id_gate juga diterima).
ipaddrsIP atau IP:port. Kosong = IP pengirim. Port bawaan 80.
snOpsional. Serial number Interface, maks. 64 karakter (huruf, angka, . _ : - /). Kosong = nilai lama.

Respons berhasil (200)

{ "status": true, "gate": "GATE MASUK", "ip": "192.168.18.30", "port": 80, "sn": "SERIAL123", "berubah": true }

Respons gagal

KodePesan
400apikey tidak valid
400ipaddrs tidak valid, contoh: 10.10.1.2 atau 10.10.1.2:80
400ipaddrs x.x.x.x bukan jaringan lokal yang sama dengan server
400sn tidak valid (maks 64 karakter: huruf, angka, . _ : - /)
404apikey tidak terdaftar

5. Akses member ANPR

GET/api/gate/akses_member_anpr

Member masuk lewat pembacaan plat nomor (ANPR). Bila nopol milik member yang memenuhi ketentuan, kendaraan dicatat masuk di gate ini dan gate dibuka.

http://IP-SERVER:3003/api/gate/akses_member_anpr?id_gate=KEY&nopol=BK1234AB
ParameterKeterangan
id_gateWajib. API key Interface (gate masuk).
nopolWajib. Hasil baca plat. Huruf besar, spasi dan tanda baca diabaikan (bk 1234 ab = BK1234AB).
  • Nopol dicocokkan ke kendaraan di menu Langganan.
  • Syarat: langganan Aktif, masa berlaku mencakup hari ini, belum tercatat di area, dan jenis kendaraan (tarif) sudah diatur.
  • Dicatat seperti kendaraan masuk member: metode_masuk = anpr, anpr_masuk = nopol hasil baca, no. tiket = nomor kartu RFID (bila tidak ada: 10 digit acak). Server membuka gate dan foto diambil di latar belakang.

  "gate": "GATE MASUK",
  "jenis_kendaraan": "mobil",

  "member": "NAMA",
  "nopol": "BK1234AB",
  "gate_dibuka": true
}

7. Buka gate (server → Interface)

GEThttp://IP-INTERFACE:PORT/open-gate/?sn=SERIAL

Endpoint ini harus tersedia di perangkat Interface. Server memanggilnya setelah kendaraan masuk tercatat, dan setelah kasir menyelesaikan pembayaran di gate keluar.

  • IP-INTERFACE:PORT diambil dari menu Perangkat (atau dari Update IP).
  • sn = serial number Interface yang tersimpan di server (tidak dikirim bila belum ada); Interface sebaiknya menolak bila tidak cocok. Port 80 tidak ditulis di alamat.
  • Batas waktu 3 detik. Balasan Interface tidak ditunggu oleh API masuk; kegagalan dicatat di log server.
  • Path dapat diganti dengan GATE_OPEN_PATH di .env.

8. Laporan omset (bot WhatsApp)

  • Permintaan GET, tanpa login dan tanpa API key. Bisa lewat IP server maupun domain.
  • Data dari transaksi parkir yang sudah dibayar, per tanggal buku (bukan tanggal kalender). Pembayaran langganan dan pendapatan manual tidak dihitung.
  • Selalu untuk tanggal buku berjalan, tanpa parameter.
  • Respons JSON: ok dan message (teks siap kirim ke WhatsApp).
GET/RestApi/OmsetNow

Omset per kasir pada tanggal buku berjalan, total transaksi, total omset, dan kendaraan di area.

http://IP-SERVER:3003/RestApi/OmsetNow

Respons berhasil (200)

{
  "ok": true,
  "message": "📊 *LAPORAN OMSET PARKIR*\n━━━━━━━━━━━━━━━━━━\n📅 Tanggal: *14/10/26*\n..."
}

Transaksi tanpa kasir (keluar otomatis lewat gate) memakai nama gate keluar di daftar kasir.

GET/RestApi/OmsetRekap

Rekap omset harian satu bulan: tanggal 1 sampai tanggal buku berjalan, total omset, jumlah kendaraan, dan jumlah kendaraan per metode bayar.

http://IP-SERVER:3003/RestApi/OmsetRekap

Respons berhasil (200)

{
  "ok": true,
  "message": "📊 *REKAP OKTOBER*\n```\nKam  01/10/26   557.000\n...\nTOTAL            7.290.000\n...```"
}

Respons gagal

9. SDK QRIS

  • Alamat SDK diisi di menu Perusahaan → SDK QRIS, berupa alamat dasar tanpa path, misalnya http://localhost:5000. Boleh http:// (termasuk localhost) atau https://.
  • SDK wajib menyediakan dua endpoint GET di bawah ini dengan parameter dan format respons yang sama persis (standar).
  • Semua respons JSON dan selalu memuat status (true/false).
  • Tombol Test di samping isian SDK QRIS: pilih printer yang sedang online (menu Perangkat) dan nominal, lalu Cetak. Server memanggil SDK (jadi localhost = mesin server), menampilkan QR, lalu Cek status untuk melihat apakah sudah dibayar.
  • Kasir: bila Link SDK QRIS diisi dan metode bayar yang dipilih bernama/berkode qris (huruf besar/kecil bebas), popup QRIS langsung muncul begitu metode QRIS dipilih dan tarif sudah dihitung (jenis kendaraan dipilih). QR dicetak ke printer Interface kasir, status dicek otomatis tiap ±2,5 detik (popup hanya bisa ditutup lewat tombol Batal; Esc dan klik di luar tidak menutup); begitu lunas transaksi langsung selesai, struk tampil, dan gate dibuka. Server mengecek ulang lunas ke SDK sebelum menyimpan; no. tagihan masuk no_referensi pendapatan dan respons bank masuk catatan transaksi parkir.
  • Bayar dari HP: bila Payment link (menu Perusahaan) diisi, QR tiket masuk berisi {Payment link}/payment/{no tiket}. Halaman itu (tanpa login) menampilkan tarif, membuat QRIS lewat SDK, dan mengecek status otomatis. Tarif Rp 0 → muncul pesan tarif masih nol (belum perlu bayar). Setelah bayar, tiket tampil Sudah bayar online di kolom Pembayaran In Area. Saat keluar, kasir scan tiket dan tarif dihitung ulang dikurangi yang sudah dibayar: kekurangan > 0 dibayar seperti biasa (tunai / QRIS); kekurangan Rp 0 → transaksi langsung selesai, struk dicetak, gate dibuka. Pendapatan dicatat 2 baris: bagian online (QRIS) dan kekurangan. Kasir tetap bisa scan QR berisi URL maupun mengetik no. tiket.
GET/api/qr/?amount=NOMINAL&ip-printer=IP-PRINTER

Membuat tagihan QRIS di bank dan mengembalikan gambar QR (base64). Bila ip-printer diisi, QR juga dicetak ke printer thermal LAN tersebut.

http://localhost:5000/api/qr/?amount=1&ip-printer=192.168.18.208
ParameterKeterangan
amountWajib. Nominal tagihan (bilangan bulat > 0)
ip-printerOpsional. IP printer thermal LAN untuk mencetak QR

Respons berhasil (200)

{
  "status": true,
  "billing_number": "1792557548956",
  "amount": 1,
  "printed": true,
  "qr_base64": "iVBORw0KGgoAAAANSUhEUgAA..."
}
  • billing_number = nomor tagihan, dipakai untuk cek status pembayaran.
  • printed = true bila QR berhasil dicetak; false bila gagal atau ip-printer tidak diisi.
  • qr_base64 = gambar QR (PNG base64), tampilkan dengan data:image/png;base64, + isinya.

10. SDK Uang Elektronik

  • Alamat SDK diisi di menu Perusahaan → SDK uang elektronik, berupa alamat dasar tanpa path, misalnya http://localhost:4173. Boleh http:// (termasuk localhost) atau https://.
  • SDK terhubung ke reader kartu (e-money Mandiri, BRIZZI, TapCash, Flazz) dan wajib menyediakan endpoint di bawah ini. Body dan respons berupa JSON.
  • Tombol Test di samping isian: cek koneksi reader, Cek saldo kartu yang ditempel, dan Test potong sesuai nominal (kartu benar-benar terpotong). Sesi tes yang belum lunas dibatalkan saat popup ditutup.
  • Kasir: bila link SDK diisi dan metode bayar yang dipilih bernama/berkode uang elektronik, e-money, atau kartu, popup Tempelkan kartu muncul. Server membuat satu no. transaksi (transactionId, awalan HP) lalu setiap tap memanggil /api/parking/deduct dengan no. transaksi dan nominal yang sama sampai lunas. Nominal ditandatangani server, jadi tidak bisa diubah dari browser.
  • Sebelum transaksi disimpan, server mengecek ulang ke /api/payments/{transactionId}: status harus paid dan nominal sama dengan tarif. No. transaksi masuk no_referensi pendapatan dan tidak bisa dipakai dua kali.
  • Pendapatan dicatat sesuai jenis kartu dari awalan nomor kartu: 6032 E-money Mandiri, 6013 BRIZZI BRI, 7546 TapCash BNI, 0145 Flazz BCA. Metodenya dibuat otomatis bila belum ada (tidak tampil di kasir). Nomor kartu disimpan tersamar.
  • Popup ditutup sebelum lunas → server memanggil /cancel agar kartu tidak terpotong belakangan.
  • Angkat kartu begitu reader berbunyi. Reader baru mengirim hasil deduct ke komputer setelah kartu diangkat; kartu yang dibiarkan menempel membuat hasil tertahan ±10 detik (diukur: diangkat 4 dtk, dibiarkan 9–11 dtk termasuk waktu menempel).
  • Metode gabungan QRIS + uang elektronik: buat metode bayar yang nama/kodenya mengandung qris dan uang elektronik / e-money / kartu (mis. QRIS + Uang Elektronik, kode QRIS_EMONEY), dan isi kedua link SDK. Popup kasir menampilkan QR sekaligus menunggu kartu ditempel; yang lunas duluan menyelesaikan transaksi dan pendapatan dicatat sesuai channel yang dipakai (QRIS, atau jenis kartu). Channel lain dihentikan: sesi kartu dibatalkan, status QRIS masih dipantau 30 detik. Bila pelanggan terlanjur membayar dua kali, kasir mendapat peringatan untuk mengembalikan kelebihan, dan pembayaran kedua dicatat di catatan transaksi parkir (pembayaran_ganda, bukan pendapatan). Bila hanya satu link SDK diisi, metode ini berlaku sebagai QRIS saja / kartu saja.
POST/api/parking/deduct

Satu tap kartu: reader memotong seluruh tagihan dari kartu yang ditempel. Bila gagal (mis. saldo kurang), kartu tidak dipotong; kirim ulang permintaan yang sama setelah kartu ditempel lagi. No. transaksi yang sama aman diulang (tidak memotong dua kali).

POST http://localhost:4173/api/parking/deduct
Content-Type: application/json

{"transactionId":"HP5-MH3K2Q1A7","amount":5000,"gateId":"KASIR-1"}
FieldKeterangan
transactionIdWajib. No. transaksi, sama untuk setiap tap sampai lunas
amountWajib. Nominal tagihan (bilangan bulat)
gateIdOpsional. Nama perangkat kasir/gate (maks. 20 karakter)

Respons lunas (200)

{
  "success": true,
  "transactionId": "HP5-MH3K2Q1A7",
  "status": "paid",
  "amount": 5000,
  "paid": 5000,
  "remaining": 0,
  "balance": 45000,
  "payments": [{ "cardNo": "6032984012344438", "cardType": "01", "amount": 5000, "balance": 45000, "transactionDate": "..." }],
  "reader": { "statusCode": "000000", ... },
  "barrier": { "requested": true }
}

Respons belum lunas (200)

{
  "success": false,
  "status": "open",
  "remaining": 5000,
  "sameCard": { "cardNo": "6032 98** **** 4438", "retriesLeft": 2 },
  "message": "Saldo kartu kurang, kartu tidak dipotong. Isi saldo lalu tempel KARTU YANG SAMA (6032 98** **** 4438) untuk Rp 5.000. Sisa percobaan 2",
  "reader": { "statusCode": "011004", ... }
}
  • success = true atau status = "paid" → lunas. Selain itu tap diulang dengan transactionId dan amount yang sama.
  • reader.statusCode 011002 = reader menunggu kartu terlalu lama (belum ada kartu ditempel): kasir langsung mengulang tap tanpa pesan error.
  • sameCard = kartu yang saldonya kurang; 3 tap berikutnya harus kartu yang sama (kartu lain ditolak tanpa dipotong). null = kartu apa pun boleh.
  • payments = kartu yang terpotong (nomor, jenis, nominal, saldo akhir). Respons lunas lengkap ikut disimpan di catatan transaksi.

Respons gagal

KodeRespons
400{"success":false,"error":"transactionId is required"} / "amount must be a non-negative integer"
409{"success":false,"error":"Reader is not connected"}
502{"success":false,"deducted":true,"error":"..."} kartu sudah terpotong tetapi palang SDK gagal; tetap dianggap hasil pembayaran

http://localhost:4173/api/payments/HP5-MH3K2Q1A7

Respons berhasil (200)

{
  "success": true,
  "transactionId": "HP5-MH3K2Q1A7",
  "status": "paid",
  "amount": 5000,
  "paid": 5000,
  "remaining": 0,
  "payments": [{ "cardNo": "6032984012344438", "cardType": "01", "amount": 5000, "balance": 45000, "transactionDate": "..." }]

  • Tidak ditemukan → 404 {"error":"Transaction not found"}.
POST/api/payments/{transactionId}/cancel

Menutup sesi yang belum lunas (body {}). Sesi yang sudah lunas tidak berubah dan dijawab dengan statusnya. Respons sama dengan status sesi; 404 bila tidak ditemukan, 409 bila tap kartu masih berjalan.

GET/api/parking/health
